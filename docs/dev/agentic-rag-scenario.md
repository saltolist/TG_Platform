# Сценарий: Agentic Graph RAG на разных типах запросов

> **Deprecated** — описывает **legacy** L2 (resolvers, plan alignment, referent
> router). Целевое поведение: [rag-pipeline/README.md](rag-pipeline/README.md)
> (ADR-011). Сохранён для regression до миграции на LangGraph.

> **Статус:** эталонное поведение (спецификация), иллюстрирует модель из
> [ADR-008](adr/008-agentic-graph-rag.md) и приоритеты из
> [Роадмап: Agentic Graph RAG](roadmap-agentic-rag.md). Реализации пока нет —
> документ фиксирует ожидаемую трассировку **до** написания кода, чтобы потом
> сверять поведение и тесты с ним.

Связанные документы: [ADR-008](adr/008-agentic-graph-rag.md),

## 1. Тестовые данные (общие для всех сценариев)

**Пост `post-1`** («Мартовский дайджест», published, есть в канале):

```json
{
  "id": "post-1",
  "text": "Подводим итоги марта! Портфель показал уверенный рост. Подробный разбор — в закреплённой заметке ниже.",
  "media": [{ "name": "chart_march.jpg", "url": "...", "type": "image/jpeg" }],
  "notes": [
    {
      "id": "n1",
      "title": "Итоги Q1",
      "body": "Полные результаты доходности по месяцам. См. [приложенный отчёт](attachment:f1).",
      "files": [{ "id": "f1", "name": "Отчёт_Q1.pdf", "url": "...", "type": "application/pdf" }]
    }
  ],
  "comments": [
    { "id": "c1", "author": "Аня", "text": "Отличный результат!" },
    { "id": "c2", "author": "Игорь", "text": "Почему так мало заработали в марте?" },
    { "id": "c3", "author": "Вика", "text": "А когда следующий разбор?" }
  ]
}
```

> **Как это индексируется.** Ссылка `attachment:f1` в `body` — обычный markdown
> по [формату заметок](note-format.md). При индексации (`markdown_to_index_text`)
> она **вырезается**, остаётся только текст ссылки — эмбеддится и хранится как
> `note_chunk`:
>
> ```
> Полные результаты доходности по месяцам. См. приложенный отчёт.
> ```
>
> Сама ссылка `attachment:f1` в эмбеддинге не участвует — её физически там нет.
> Чтобы сигнал 2 (Ярус A, [ADR-008](adr/008-agentic-graph-rag.md)) вообще мог
> сработать, id вложений извлекаются **отдельным regex-проходом по сырому
> `body`** ещё до зачистки и сохраняются рядом с чанком как метаданные
> (`referenced_attachment_ids: ["f1"]`), а не как часть текста для поиска. Это
> и есть то, что чанк «ссылался на `attachment:f1`» в сценариях 3–4 ниже.

**Глобальная заметка `n-global-1`** («Стратегия на 2026», без вложений):

```json
{ "id": "n-global-1", "title": "Стратегия на 2026", "body": "60% акции, 30% облигации, 10% кэш. Ребалансировка раз в квартал." }
```

**Проиндексировано (L1, до всех сценариев):** `post_text` поста, `note_chunk`
обеих заметок, `media_meta` картинки (только имя файла). `attachment_text` для
`f1` **ещё не проиндексирован** (write-time extraction ещё не выполнялась —
показательно для сценария 3).

## 2. Сценарии

### Сценарий 1 — L0: RAG не нужен вообще

**Запрос (global chat):** «Спасибо, отлично!»

| Шаг | Результат |
|---|---|
| L0 | Реплика без предметного вопроса → RAG пропускается |
| L1 / L2 | Не запускаются |

**Итог:** ответ собирается из bundle + истории, без единого обращения к retrieval.

---

### Сценарий 2 — L1 полностью достаточен

**Запрос (global chat):** «Какая у меня стратегия распределения активов?»

| Шаг | Результат |
|---|---|
| L0 | Есть предметный вопрос → продолжаем |
| L1 | top-hit: `note_chunk` «Стратегия на 2026», similarity 0.86 |
| Ярус A | Не промах и не известная ссылка → fast-path не срабатывает, признаки: `pointer_phrase=false`, `answer_type_mismatch=false` (вопрос ожидает описание/цифры — чанк содержит цифры 60/30/10), `chunk_too_short=false`, `is_followup=false`; манифест — у заметки нет `files` |
| Ярус B | Вызывается (fast-path не сработал) → `ragReasonerModels` с пустыми/отрицательными признаками и пустым манифестом → `{sufficient: true}` |
| L2 | Не запускается |

**Итог:** `rag_context` = чанк заметки целиком. Один embed, один SQL-запрос
и один дешёвый structured-вызов Яруса B — но без agentic-цикла и без единого
LLM-вызова сверх ответной модели, кроме этого дешёвого чека.

---

### Сценарий 3 — Успешный L1, но контекста недостаточно (прямая ссылка в чанке)

**Запрос (post chat, открыт `post-1`):** «Какая была точная доходность в отчёте?»

| Шаг | Результат |
|---|---|
| L1 | top-hit: `note_chunk` «Итоги Q1» (similarity 0.81) — текст: «Полные результаты… См. приложенный отчёт» |
| Ярус A, сигнал 2 | Чанк ссылался на `attachment:f1` при индексации; `attachment_text` для `f1` не проиндексирован и не в результатах L1 → **эскалация с известной целью** |
| Ярус A, сигнал 3 | Pointer-фраза «см. приложенный» подтверждает сигнал 2 |
| Ярус A, сигнал 4 | Вопрос ожидает число («точная доходность»), в чанке цифр нет |
| Ярус B | Не нужен — Ярус A уже дал `open_next = attachment:f1` |
| L2, шаг 1 | `HydrateAttachment("f1", mode="text")` — файла ещё нет в `attachment_text` → lazy-путь: скачать с MinIO, извлечь текст, **закэшировать** в `attachment_text` |
| L2, шаг 2 | Planner: контент получен, есть цифры → `Stop(sufficient)` |

**Итог:** `rag_context` = чанк заметки + извлечённый текст PDF. Один
дополнительный LLM-вызов (planner) + одна операция извлечения файла (разовая —
второй такой же вопрос уже пойдёт через L1, см. Сценарий 7).

### Сценарий 4 — Multi-hop: пост → заметка → вложение

**Запрос (global chat, пост не открыт явно):** «Что мы писали про итоги марта?»

| Шаг | Результат |
|---|---|
| L1 | top-hit: `post_text` «Мартовский дайджест» (similarity 0.83) — это вступление, без цифр |
| Ярус A | Не промах и нет известной ссылки на вложение (это `post_text`, не чанк заметки) → fast-path не срабатывает; признак `pointer_phrase=true` («в закреплённой заметке ниже»), манифест поста показывает непройденную заметку `n1` |
| Ярус B | Вызывается → признак `pointer_phrase` + непройденный сосед в манифесте → `{sufficient: false, open_next: ["note:n1"]}` |
| L2, шаг 1 | `ListPostNotes("post-1")` — бесплатно, `notes[]` уже в JSONB поста из top-hit |
| L2, шаг 2 | `OpenNote("n1")` → тот же чанк, что и в Сценарии 3 → снова pointer на `attachment:f1` |
| L2, шаг 3 | `HydrateAttachment("f1", mode="text")` → теперь уже **бесплатно** (закэшировано в Сценарии 3) |
| L2, шаг 4 | `Stop(sufficient)` |

**Итог:** цепочка **пост → заметка → вложение** пройдена за 3 шага planner'а,
в рамках `RAG_AGENT_MAX_STEPS=4`, плюс один дешёвый вызов Яруса B до входа в
L2 (структурная проверка, не генерация). Иллюстрирует именно ту цепочку, ради
которой вводился agentic-цикл.

### Сценарий 5 — Нужна картинка (vision)

**Запрос (post chat, `post-1`):** «Что изображено на графике в этом посте?»

| Шаг | Результат |
|---|---|
| L1 | `media_meta` содержит только имя файла `chart_march.jpg` — недостаточно, чтобы ответить на «что изображено» |
| Ярус A | Не промах, нет известной ссылки на вложение → fast-path не срабатывает; признак `answer_type_mismatch=true` (вопрос ожидает визуальное описание, найденный контент — только имя файла) |
| Ярус B | Вызывается → признак `answer_type_mismatch` + непройденное медиа в манифесте → `{sufficient: false, open_next: ["media:chart_march.jpg"]}` |
| L2, шаг 1 | `HydrateAttachment(media_ref, mode="vision")` → вызов `visionModels` из профиля → текстовое описание графика |
| L2, шаг 2 | `Stop(sufficient)` |

**Итог:** единственный vision-вызов за весь запрос (лимит `RAG_AGENT_MAX_VISION=1`
не превышен). Результат кэшируется по хэшу файла — повторный вопрос про эту же
картинку в другом чате не вызовет vision заново.

---

### Сценарий 6 — Чтение комментариев

**Запрос (post chat, `post-1`):** «Есть ли негативные комментарии под этим постом?»

| Шаг | Результат |
|---|---|
| L1 | top-hit: `post_text` «Мартовский дайджест» (это же post chat) — про итоги, не про реакцию аудитории |
| Ярус A | Не промах, нет известной ссылки → fast-path не срабатывает; признак `answer_type_mismatch=true` (лексика «комментари» ожидает комментарии, чанк — вступление поста; комментарии не индексируются заранее, поэтому в результатах L1 их в принципе быть не может) |
| Ярус B | Вызывается → признак `answer_type_mismatch` + манифест поста показывает `comments_count: 3` → `{sufficient: false, open_next: ["comments:post-1"]}` |
| L2, шаг 1 | `ListPostComments("post-1")` — бесплатно, `comments[]` уже в JSONB поста |
| L2, шаг 2 | Planner видит комментарий `c2` («Почему так мало заработали в марте?») как потенциально негативный → `Stop(sufficient)` |

**Итог:** комментарии прочитаны без отдельного embedding-индекса, одним
дешёвым структурным чтением.

### Сценарий 7 — Follow-up + эффект кэша

**Запрос (тот же чат, следующим сообщением после Сценария 3 или 4):**
«А там же было что-то про облигации?»

| Шаг | Результат |
|---|---|
| L1 | Запрос с history-expansion включает предыдущий контекст про отчёт → embedding теперь ближе к уже проиндексированному `attachment_text` файла `f1` (закэширован в Сценарии 3/4) |
| Ярус A | Не промах и не новая непройденная ссылка (файл уже раскрыт в этом чате) → fast-path не срабатывает, признаки отрицательные |
| Ярус B | Вызывается → содержимое чанка уже отвечает на вопрос по существу → `{sufficient: true}` |
| L2 | Не запускается |

**Итог:** то, что в первый раз потребовало agentic-цикла, во второй раз
закрывается **одним L1** — прямой эффект write-time/lazy-кэширования вложений.

### Сценарий 8 — Честный отказ вместо галлюцинации

**Запрос (global chat):** «Сколько раз мы упоминали слово "дивиденды" в марте?»

| Шаг | Результат |
|---|---|
| L1 | Низкая similarity по всем узлам (такого текста в данных нет) |
| Ярус A, сигнал 1 | Промах → эскалация |
| L2 | `SearchNodes` с переформулированным запросом (rewrite-on-miss), `ListPostNotes` по паре кандидатов — ничего релевантного; `RAG_AGENT_MAX_STEPS=4` исчерпан |
| L2, завершение | `Stop(reason="budget_exhausted")` — не «sufficient», но лимит достигнут |

**Итог:** `rag_context` собирается из лучшего, что нашли (возможно, пусто).
System prompt ответной модели требует не придумывать число, а сказать прямо:
«Не нашёл точного упоминания дивидендов в мартовских постах» — вместо
галлюцинации конкретной цифры.

### Сценарий 9 — Для контраста: команда действия (Приоритет 2, не реализовано)

**Запрос (post chat, `post-1`):** «Опубликуй этот пост сейчас»

Это **не** retrieval-сценарий — сюда agentic RAG (L0–L2) не подключается вообще.
Показан для контраста с двумя смыслами агентности (см. ADR-008):

| Шаг | Результат |
|---|---|
| Распознавание команды | Явный императив на действие → кандидат на `PublishPost` (Приоритет 2 роадмапа, не спроектировано в деталях) |
| Автономность | Ноль — модель **не публикует** сама, формирует предложение действия |
| Подтверждение | Пользователю показывается явное подтверждение перед фактическим вызовом `POST /posts/{post_id}/publish/` |

**Итог:** в отличие от Сценариев 1–8, где planner решает **автономно**, здесь
результат — только предложение, которое требует явного шага пользователя.

## Сценарий 10 — Global chat: L1 нашёл post-заметку → авто-L2

**Запрос (global chat):** «Почему зашёл мой пост про бутылки?»

**Данные:** `post_text` поста 119 в `scope=global`; заметка «Почему этот пост
зашёл» в `scope=post`.

| Шаг | Действие |
|-----|----------|
| L1 | Cross-scope merge находит `note_chunk` поста 119 |
| Tier A | `fast_path=post_note`, `escalate_target=note:n119`, Tier B пропущен |
| L2 seed | `OpenNote(note_id=n119, post_id=119)` |
| Stop-evaluator | Разрешает Stop только после открытия заметки |

## Сценарий 11 — Post chat: L1 нашёл чужой пост → авто-L2

**Запрос (post chat поста 119):** «Что я писал про розетки?»

## Сценарий 12 — Plan alignment: named post vs L1 note media

**Запрос (global chat):** «Какое изображение подойдёт моему **приветственному** посту?»

**Данные:** L1 top hit — `note_chunk` поста-черновика с PNG-вариантами; `post_text` welcome-поста в top-k нет.

| Шаг | Действие |
|-----|----------|
| L2 brief | `named_post_query=true`, referent «приветственный пост», `cross_post=deny` |
| L2 plan (initial) | Planner предлагает `OpenPost(721c63fe…)` из L1 note — **misaligned** |
| Plan alignment | `aligned=false`, reason=`l1_note_binding_only`; narrative ledger в trace |
| L2 replan | `SearchNodes(post_text, "приветственный пост")` → `OpenPost(3)` |
| Bindings | `resolved_target_post_id=3` после discovery + OpenPost |
| Stop-evaluator | Не принимает Stop без `resolved_target_post_id` при named post query |

**Trace (фазы):** `7. rag.L2.brief` → `7. rag.L2.plan_align` → `7. rag.L2.replan` → `7. rag.L2.ledger`

## Сценарий 13 — Dialog follow-up: artifact из prior turn (ADR-009 v1)

**Контекст (3 turn'а, chat `da4841f9`):**

| Turn | Запрос | Результат |
|------|--------|-----------|
| 1 | «Какое изображение welcome-посту?» | post 3, evidence gap |
| 2 | «А для поста про переключений?» | post 721, vision по PNG → snapshot в ledger |
| 3 | «А как же картинка с девушками?» | artifact resolver → anime PNG из ledger (dialog_artifact) |

| Шаг | Действие |
|-----|----------|
| Ledger load | `load_ledger(chat_id)` — hydrated attachment из turn 2 |
| Referent router | `dialog_artifact` (deixis «а как же» + ledger; post resolver не запускается) |
| L2 brief | `referent_type=dialog_artifact`, `cross_post_allow_refs=[attachment:…]` |
| Artifact resolver | «девушки» → ref из ledger, `compare_with_post_id=null` |
| L2 plan | `dialog_seed` → пустой plan (prior hydrated) |
| Stop | `dialog_ledger_hydrated` → `plan_complete` |
| Ledger append | snapshot turn 3 после L2 |

**Trace (фазы):** `7. rag.L2.referent_router` → `7. rag.L2.artifact_resolver` → `7. rag.L2.dialog_seed` → `7. rag.L2.plan` → `7. rag.L2.ledger_snapshot`

**Acceptance (v1, чат `0671925c`):** turn 3 «картинка с dевушками» → `dialog_artifact`, `dialog_seed`, `plan_complete` без re-hydrate.
